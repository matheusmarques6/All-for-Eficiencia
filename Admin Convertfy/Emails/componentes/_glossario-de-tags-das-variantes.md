Documento simples para responder três perguntas: **qual tag existe**, **o que ela significa** e **o que um bloco que a carrega pressupõe**. “Tag” aqui significa propriedade ou valor controlado do frontmatter, não `#hashtag` do Obsidian.

# Como ler

- **`dispositivo` é a chave atual de mecanismo.** O Estruturador pede o efeito; o Curador escolhe a variante.
- **`momento` e os demais eixos antigos continuam documentados para compatibilidade**, mas `momento` não deve voltar a ser a chave principal.
- **`exige` elimina.** Se um requisito não existe ou não pode ser confirmado, o bloco não pode ser usado.
- **`convivencia` restringe a composição.** A variante pode ser válida sozinha e inválida ao lado de outro bloco.
- Peças marcadas **(legada)** são referências históricas, nunca candidatas.

# Propriedades do bloco

| Propriedade | Explicação | O bloco pressupõe |
|---|---|---|
| `tipo` | Tipo documental; nas variantes, `componente`. | O arquivo segue o contrato de nota de componente. |
| `slug` | Identificador humano e nome do arquivo. | É único e estável para wikilinks. |
| `secao` | Família estrutural do bloco. | Define onde o bloco pode ser montado. |
| `nome_no_banco` | Nome literal do registro no banco. | Permite reconciliar nota e sistema mesmo quando o slug é mais claro. |
| `variant_id` | UUID do registro canônico. | Valor `null` significa que a nota não possui cadastro e não pode competir. |
| `ativa` | Chave de elegibilidade. | Somente `true` pode concorrer, salvo outros bloqueios. |
| `legado` | Marca de preservação histórica. | A nota fica fora do conjunto canônico e da seleção. |
| `status` | Estado documental. | O consumidor respeita aprovação, inatividade, ausência de julgamento ou legado. |
| `dispositivo` | Mecanismo: o que o bloco faz com o leitor. | É a chave atual pedida pelo Estruturador. |
| `peca_inteira` | Indica que a variante é o e-mail completo. | Não deve ser combinada como um bloco comum. |
| `espelho_de` | Relaciona um registro reutilizado em outra seção. | O espelho reaproveita a variante canônica e pode mudar de dispositivo conforme o papel. |
| `momento` | Contextos de disparo compatíveis. | Campo legado de filtro; não é mais a chave principal. |
| `momento_vetado` | Contextos proibidos. | Qualquer correspondência elimina a variante. |
| `objecao` | Barreira que o bloco ajuda a remover. | A mensagem precisa atacar a objeção declarada. |
| `registro` | Tom visual e verbal compatível. | A identidade da marca sustenta esse tom. |
| `registro_vetado` | Tons incompatíveis. | Qualquer correspondência elimina a variante. |
| `paleta` | Sistema cromático compatível. | Cores e contraste disponíveis permitem executar o layout. |
| `papel_na_peca` | Função do bloco na sequência. | A posição real corresponde a abrir, apoiar, desenvolver, fechar, servir de ponte ou ocupar a peça inteira. |
| `exige` | Requisitos duros. | Todos precisam existir; ausência elimina a variante. |
| `product_slots` | Quantidade de produtos endereçáveis. | Existem dados, imagens e destinos para preencher os slots. |
| `itens` | Faixa mínima e máxima de itens. | O conteúdo disponível cabe dentro do intervalo. |
| `peso` | Altura, classe e fonte da medição. | A arquitetura do e-mail comporta a carga visual. |
| `convivencia` | Restrições de combinação. | O restante da peça respeita todas as regras listadas. |
| `aprendizados` | Wikilinks para leis aprendidas. | A geração respeita essas regras transversais. |
| `serve_estruturas` | Estruturas em que a variante foi validada. | É evidência de adequação, não exclusividade. |
| `fonte` | Proveniência da nota. | Permite auditar de onde veio a descrição. |
| `densidade_no_banco` | Densidade antiga do cadastro. | É contexto legado, não decisão isolada. |
| `schema_campos` | Número de campos de saída esperados. | O pipeline possui endereços suficientes para preencher o bloco. |

# Campos quantitativos e referências

| Campo | Valores/formato | O bloco pressupõe |
|---|---|---|
| `product_slots` | 0, 1, 2, 3, 4 ou 9 nas notas atuais. | Pressupõe essa quantidade de produtos com dados e destinos. |
| `itens` | Objeto `{ min, max }` ou `null`. | Pressupõe conteúdo dentro da faixa; menos deixa buraco, mais estoura o desenho. |
| `peso.altura_px` | Altura em pixels. | Pressupõe espaço suficiente na peça e ajuda a evitar e-mails longos demais. |
| `peso.fonte` | `medido`, `estimado` ou `declarado`. | Indica o grau de confiança da altura; estimativa pede cautela. |
| `schema_campos` | Contagem de slots no schema. | Zero pressupõe que o bloco ainda não pode receber saída estruturada com segurança. |
| `aprendizados` | Lista de wikilinks. | As leis ligadas são restrições semânticas adicionais. |
| `serve_estruturas` | Lista de wikilinks. | Mostra onde houve validação concreta, sem impedir outros usos. |
| `fonte` | Texto de proveniência. | Permite distinguir inventário antigo, revisão e sincronização do Supabase. |
